# Word artwork workflow

The catalog contains 2,985 static entries. Each starts as a candidate until reviewed, except the 24 pilot subjects, which start eligible. Classification and production status are separate: an unillustrated subject is never automatically excluded.

Run commands from `imposter-game` with `npm run artwork -- <command>`. Run one command at a time; commands use an exclusive lock.

1. `init` creates `output/word-artwork/manifest.json` without replacing an existing manifest. `inventory` reports classification, production status, and coverage.
2. `classify --file <review.json>` imports a complete semantic review. Its shape is `{ "schemaVersion": 1, "entries": [{ "id": "objects-easy-umbrella", "eligibility": "eligible", "depictedMeaning": "An open handheld rain umbrella", "exclusionReason": null }] }`. Include every catalog ID exactly once. Excluded entries need a concrete reason; all pilot subjects remain eligible. Changing a depicted meaning invalidates an earlier artwork approval. Optional `sharedWith` and `equivalenceReason` fields explicitly review an equivalent depicted subject. Omitted sharing fields preserve existing reviews; `sharedWith: null` removes an alias.
3. `queue --limit 24` writes an ordered, resumable `queue.json` with complete prompts. Produce each subject separately using its prompt and request a transparent background. The current template is version 2: calm matte dimensional forms, natural proportions, unobtrusive facial features, and no glow, cast shadow, checkerboard, or unnecessary companion. Queue output states its version; creating a queue never relabels earlier images. The queue and imports are restricted to the pilot until its QA gate passes. No generation service is called by this script.
4. `import <id> <source-file> --prompt-file <prompts.json> --prompt-version 2` saves an untouched, content-addressed original and a 512 × 512 WebP derivative. The prompt file can be plain text or a JSON object mapping each canonical ID to its exact prompt string or `{ "prompt": "...", "promptVersion": "2" }`. Exact current queue prompts identify their version automatically; specify `--prompt-version 1` when importing earlier work. The manifest retains that text unchanged, its hash, version, source file hash, and original image hash. Use `record-prompt <id> --prompt-file <file>` to attach missing provenance to an already imported image without processing it again; `review` also accepts these prompt flags. Import validates real alpha, clear edges, nonempty subject, and minimum source dimensions. It does not remove backgrounds, crop subjects, recolor, or touch up pictures. Originals are never overwritten. Reimporting unchanged bytes preserves review state. A different original returns the entry to generated status and requires its own prompt; earlier prompt records remain in history.
5. `contact-sheet` creates a local HTML review page with white and dark backgrounds. Inspect subject accuracy, useful silhouette, appropriate crimson `#B6192E` details, unclipped edges, absence of text or extra clues, and clarity at small sizes. Alpha checks cannot detect a checkerboard drawn inside an otherwise transparent image; visual review is required.
6. `review <id> approved --notes "<specific review findings>"` approves a visually checked image with complete prompt provenance. Use `rejected` for a failed image. Rejected entries return to the generation queue. Import alone does not approve artwork.
7. `build` copies only approved derivatives into `assets/word-illustrations` and produces the literal asset references in `data/wordIllustrations.ts`. Equivalent shared entries reference one runtime file. Unapproved or absent artwork resolves to the existing text presentation. `data/wordIllustrationIds.ts` separately lists eligible canonical IDs without importing any assets, so pure round generation cannot attach an excluded subject's image ID. Classification, alias ingestion, and builds also emit `../supabase/functions/generate-round/catalog/illustration-senses.ts` from every eligible depicted meaning, including subjects whose images are still pending. This server-owned lookup keeps translation meaning aligned with the reviewed depiction without requiring a deployment for each completed image batch. Do not hand-edit generated lookups; update the semantic review and rebuild. Validation checks exact parity. Test roots write their own server output and never touch the application backend.
8. After all 24 images are approved, built, and actually checked in the app, record `pilot-qa --checks visual,interaction,offline --notes "<tested devices, subjects, and observed results>"`. Check the full pilot, small screens, large text, translations, hold/release, handoff, backgrounding, reduced motion, screen reader, and offline use. The gate requires complete artwork, provenance, current runtime assets and registry, and size budgets. It records the operator's checks; it does not perform them. An import/review change to a pilot subject invalidates the gate.
9. Continue with queue batches of at most 24. Run `validate` after builds and `report` to save `coverage-report.json`. `artworkReady` remains false while any candidate or eligible subject is unresolved, the pilot QA gate is pending, artwork validation fails, or size budgets are exceeded. `releaseReady` additionally requires separate final production release evidence. A pilot fixture, including a fixture with verified network denial, does not by itself establish final production, device-network-off, spoken VoiceOver, or language-review proof.

Runtime assets target a mean of 40 KiB; files above 100 KiB are flagged. Review outliers before release. The full-resolution originals, prompts, review manifest, contact sheet, and coverage report stay under `output/word-artwork` and are not imported by the app. Source, derivative, and runtime hashes make accidental replacement detectable. The generation queue has no influence on word selection, category weights, or difficulty.

## Reviewed equivalents

Use `aliases --file <alias-review.json>` for a separate, partial equivalence review: `{ "schemaVersion": 1, "entries": [{ "id": "<canonical alias ID>", "sharedWith": "<canonical source ID>", "equivalenceReason": "Why both terms name the same depicted subject" }] }`. IDs must exist in the catalog. An alias and its source must be eligible; the source must be standalone. Self references, chains, cycles, missing reasons, and aliases from any of the 24 pilot subjects are rejected. A pilot image may serve as the source for a reviewed nonpilot equivalent. This is an explicit editorial review; matching strings never create an alias.

Potential equivalents include couch/sofa, an electric torch/flashlight, and equivalent category entries for the same action. Check the actual catalog IDs and meanings before recording any pair: a burning torch is not an electric flashlight, and the same word in two categories may have different senses. Existing explicit couch/sofa reviews from the first manifest format receive a recorded compatibility reason when a review is ingested.

Each equivalence records hashes of both reviewed meanings. Changing either meaning requires renewing the review with an explicit reason or removing the alias; stale reviews cannot silently keep sharing. The generated backend lookup uses the source's depicted meaning for every alias. Once that source is visually approved, both canonical IDs refer to one runtime asset. Run `build` after alias ingestion to refresh the client registry.

## Final release evidence

After the complete library is ready, `release-qa --evidence-file <file.json>` records final checks. The file requires four sections: `productionBuild`, `offline`, `voiceOver`, and `languageReview`. Every section needs specific `notes` and an `evidencePath` pointing to an existing, nonempty file below the app's `output` directory. Add `configuration: "production"` and `buildId` to productionBuild; `method: "device-network-disabled"` or `"production-network-denial"` to offline; the tested `device` to voiceOver; and a `languages` array identifying reviewed non-English languages to languageReview. Record exactly the method used: controlled denial must not be called device networking disabled.

The command records the operator's evidence rather than performing these checks. It requires complete artwork and current generated lookups, hashes each evidence file, and binds approval to the current images, depicted meanings, aliases, and pilot review. Missing or changed evidence, or later artwork changes, keep `releaseReady` false. Earlier prompt records and pilot checks are retained separately.

If a process is forcibly stopped and leaves `.pipeline.lock`, verify no artwork command is running before removing that lock and retrying. The manifest is saved with an atomic rename, so completed imports and reviews are resumable.
